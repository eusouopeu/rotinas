# Migração React/Vite — estado e limites

`webapp/` é uma reescrita incremental. Não tente concluir a migração numa tarefa.

**Corte de produção em Android/Electron (05/09/2026)** — por pedido explícito do Pedro, aceitando os gaps abaixo em vez de esperar paridade total: `capacitor.config.json:webDir` e `electron/main.js` passaram a apontar para `webapp-dist` (build React) em vez de `www` (cópia do legado); `package.json` (`sync`/`apk`/`desktop:start`/`desktop:build`/`build.files`) segue o mesmo apontamento. `android/app/build.gradle` foi para `versionCode 34`/`versionName "2026.09.05-34"`, `npm run apk` rodou limpo e o APK foi validado (`aapt dump badging` + `apksigner verify`, assinado com o `brita.keystore` estável — instala por cima do anterior, sem exigir desinstalar). O legado na raiz (`index.html`) continua existindo como fonte de leitura para lógica ainda não portada, e pode seguir sendo usado como PWA de navegador à parte, mas **não é mais o que roda no celular/desktop do Pedro**. Gaps aceitos nesse corte, sem bloquear: MCP com wiring incompleto no lado React (nenhum `onMcpCall` registrado ainda — chamada de tool feita por fora do app trava sem resposta até isso ser portado); pontes nativas (Drive/MCP/Mini player, `lib/nativeBridge.ts`) executando pela primeira vez em produção depois de meses "inertes" — primeiro uso real pode expor bug de integração nunca visto; exclusões permanentes (PIN, atalhos globais, editor Markdown live). Se aparecer regressão, o rollback é reverter os 4 arquivos de config acima e gerar um novo APK a partir do legado.

Vite usa `root:"webapp"`, `base:"./"`, saída `webapp-dist`; TypeScript é estrito. Scripts: `dev:react`, `build:react`, `test:react`, `typecheck:react`. Estado: store Zustand e storage compatível com os mesmos formatos/dados legados. O CSS é o `app.css` raiz importado por `main.tsx`; não há Tailwind/CSS Modules. Preserve `#app`.

Portados parcialmente: Home (incluindo agenda inline "Semana"), Settings (incluindo Backup, Calendário externo, Mini player, Sincronização com nuvem e Integrações MCP), RoutineEditor/Detail, Player/Done, Metas, Notes/NoteEditor, pastas/documentos de modelo (scoreboard, thoughtrecord, proscons, mercado, matriz 2×2, kanban, viagem) e Despesas (`ExpenseFolder.tsx` — tela dedicada fora do molde genérico de doc, cada lançamento é a própria "nota").
